## 맡은 일

WordPress로 만든 글로벌 공식 사이트(국·영·중·일)를 AWS로 옮기는 작업에 참여했고(2025년 9\~12월), 2026년 1\~3월 운영 개발을 맡은 뒤 인수인계했습니다. 사이트 저장소에 남은 제 커밋은 173개이고, 대부분 이관 직후인 2025년 12월에 몰려 있습니다. 가장 많은 시간을 쓴 일은 아래 「까다로웠던 점」의 캐시 문제입니다.

## 주요 작업

- **이관 준비** — 새 Git 저장소 구성과 GitLab CI 배포 파이프라인 설정, 이관 기간에 허용된 IP 밖의 접속을 점검 페이지로 보내는 처리, 관리자별 API 접근 권한 정리.
- **채용 페이지(그린하우스 API 연동)** — 채용관리 시스템인 그린하우스의 공고를 API로 받아 보여 주는 채용 페이지를 맡았습니다. 이관 때 공고 조회(내부 공고 포함)와 검색을 확인하는 검증 스크립트를 만들었고, 이후 채용공고 목록·상세 화면을 고치고 스튜디오 구분값과 스튜디오별 채용공고 연동을 추가했습니다.
- **AWS 이관 QA** — qa·stg 환경 점검, 주가 연동 API 검증 스크립트, 도메인 변경 뒤 CloudFront 502와 WAF 정책 문제 대응, 콘텐츠 저장 테스트 케이스 작성.
- **DB 장애 전환 부하 시험** — 부하 시험용 스크립트를 만들고 JMeter로 부하를 건 상태에서 RDS Multi-AZ 장애 전환(failover)을 시험해 Datadog 지표로 확인했습니다.
- **CI 변경 반영** — 새 기업 이미지에 맞춰 폰트·로고·파비콘·이미지와 헤더·메인·페이지 스타일을 바꿨습니다.
- **의장 페이지 분리(bg.krafton.com)** — bg.krafton.com 주소를 유지한 채 www 사이트의 콘텐츠를 AJAX로 불러와 바꿔 끼우는 방식으로 만들었습니다. 상대 경로와 지연 로딩 이미지 경로를 www 절대 경로로 바꾸고, CSS·JS를 순서대로 동적 로드하고, 뒤로가기·앞으로가기는 History API로 지원합니다(40시간).
- **CloudFront 캐시 무효화** — 그때까지 IAM 권한으로 터미널에서 하던 캐시 무효화를 관리자 화면에서 할 수 있도록 AWS 공식 문서를 검토해 방법(EC2 IAM 역할 + AWS SDK for PHP, 환경별 배포 ID)을 정리하고, 기존 무효화 절차와 함께 인수자에게 넘겼습니다. 구현은 인수인계 뒤 인수자가 했습니다.
- **운영** — 보안 취약점 조치, IR·공시·채용공고 반영.

## 까다로웠던 점

- **일반 사용자가 관리자 로그인 화면으로 이동하던 문제** — 이관하면서 인프라 쪽의 강한 요구로 메인(/)과 index 경로를 반드시 캐싱하게 됐습니다. 그런데 관리자 세션이 만료될 때 보안 플러그인이 보내는 리다이렉트 응답까지 캐시에 저장되어, 같은 경로로 들어온 일반 사용자도 관리자용 로그인 페이지로 이동했습니다. 12월 15일부터 26일까지 리다이렉트 지점과 로그인 기록을 추적하며 테마 함수 파일을 90번 넘게 고쳐 원인을 좁혔습니다. 플러그인의 IP·세션 확인 방식을 바꾸고, 세션 만료 리다이렉트를 테마에서 막고, 만료된 쿠키를 지우고, 관리자 화면 응답에는 캐시 금지(no-store)를 붙여 해결했습니다. 고치는 과정에서 생긴 메인 페이지 무한 리다이렉트도 함께 막았습니다.
- **콘텐츠만 바꿔 끼우는 페이지의 정리 작업** — 의장 페이지는 페이지 전체가 아니라 콘텐츠만 교체하기 때문에, 옮겨 다닐수록 스크롤 애니메이션(ScrollMagic)·슬라이더(Swiper) 인스턴스와 이벤트·타이머가 쌓이고 같은 애니메이션이 겹쳐 생겼습니다. 전환할 때마다 인스턴스·이벤트·타이머를 정리하고, 링크 클릭과 폼 제출(IR 게시판 검색 포함)을 가로채 AJAX로 처리하게 바꿨습니다.
- **스튜디오 이름으로 안 나오던 채용공고** — 새로 연동한 스튜디오 공고가 그린하우스에 각 스튜디오가 아니라 크래프톤 보드로 등록돼 있어, 스튜디오 이름으로 찾으면 나오지 않았습니다. 이 점을 크래프톤에 알려 확인받고 연동을 고쳤습니다.
