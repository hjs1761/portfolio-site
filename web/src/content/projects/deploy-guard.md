## 맡은 일

AI 코딩 에이전트(Claude Code)가 고객사 운영 서버에 파일을 반영할 때 쓰는 안전장치를 만들었습니다. 규칙 문서에 diff → 서버본 백업 → 복사 절차가 있었지만, 최근 한 달 36건에서 복사 직전 diff는 61%, 서버본 백업은 5%였습니다. 이를 실행 직전에 검사하는 훅으로 바꿨습니다.

## 동작

- **diff 없는 복사 차단**: 「대상 서버 파일 + 올릴 로컬 파일」 쌍으로 diff 기록을 남기며, 30분만 유효합니다.
- **서버본 자동 백업**: 반영할 때마다 서버본을 백업합니다.
- **우회 경로 차단**: 제자리 편집(`sed -i` 등)과 재귀 삭제를 막습니다. 파일 하나 삭제는 백업 후 통과시킵니다.

## 까다로웠던 점

- **연결 끊김**: 원격 드라이브가 끊기면 서버 파일이 없는 파일로 보였습니다. 서버 접속과 부모 폴더 응답을 확인해야 신규 파일로 인정하도록 했습니다.
- **차단 누락과 오탐**: 서버 파일 변경 경로 10개 중 처음에는 8개가 통과해 차단했습니다. 읽기 전용 분석 스크립트도 막히는 오탐은 명령마다 맨 앞 명령어로 판정하도록 고쳤습니다.
- **diff 기록 혼동**: 파일 이름으로 기록하니 다른 로컬 파일의 diff가 엉뚱한 반영을 통과시켰습니다. 경로 쌍으로 바꿨습니다.

## 직접 해 보기

시뮬레이터는 실제 훅의 판정 함수를 옮겼습니다. 파일 시스템·현재 시각·서버 접속 확인만 가상이며, 판정 순서와 규칙은 같습니다. 명령은 실행하지 않고 문자열로 분석합니다.
