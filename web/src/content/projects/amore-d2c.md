## 맡은 일

2025년 1월 운영 개발로 합류했습니다. 2026년에는 관리자 시스템(서브어드민) 이관과 고객사 보안성 검토·ISMS 대응, 9월 서비스 종료를 주로 맡았습니다. 2026년 Jira 작업 기록은 735.6시간입니다.

## 주요 작업

- **라보에이치 CRM** — 광고성 문자 수신동의 혜택(구매 적립 1%, 수신동의 3천 원)에서 시작해, 회원 데이터 수집과 동기화, 세그먼트 자동 발송 6종과 관리자 발송 화면, 실발송·중복 차단·클릭 추적과 매출 귀속 대시보드까지 네 단계로 만들었습니다.
- **케어박스 추첨제 전환** — 선착순(재고 홀딩) 구조를 걷어내고, 기존 주문 상태는 그대로 둔 채 추첨 상태를 별도 컬럼으로 더했습니다. 데이터를 옮기지 않고도 지난 신청과 새 신청이 함께 돌아갑니다. 같은 구조를 라보에이치 힐링박스로 옮겼습니다.
- **관리자 시스템 Kubernetes 환경 구축** — 재이관을 위해 4개 몰의 DB와 소스를 나누고, 스키마 차이 정리·php-fpm·CSP 설정과 배포를 맡았습니다.
- **보안성 검토·ISMS** — 코드에 들어 있던 비밀 값을 AWS Secrets Manager로 옮기고, 전 브랜드 프론트 API의 쿼리를 prepared statement로 바꿨습니다. 보안 헤더·세션·CORS·XSS·업로드 검증과 SonarQube·모의해킹 지적 사항을 조치했고, 라보에이치몰 ISMS 점검 인터뷰·실사에 대응했습니다.
- **서비스 종료** — 메뉴·게시글 자동 숨김과 종료 안내 페이지, 3개 몰의 판매·적립금·쿠폰 사용 종료(9월 1일 0시) 반영과 모니터링, 개인정보 파기 증적 리포트, 라보에이치 뷰티포인트 전환.

## 까다로웠던 점

- **보안 검토로 멈춘 이관** — 「외부 API와 내부 관리자 영역을 나누라」는 요구가 서버·DB·도메인·프레임워크를 전부 바꾸는 논의로 커졌습니다(약 80~360인일). 요구사항 원문으로 돌아가, 관리자 화면만 별도 저장소로 떼어 내는 최소안을 냈습니다.
- **「250개 파일이 다르다」** — 두 환경의 소스 비교 결과를 다시 쟀더니 159개는 줄바꿈·들여쓰기 차이였고, 실제로 손볼 파일은 약 40개였습니다. 공수 추정이 약 24~33인일로 줄었습니다.
